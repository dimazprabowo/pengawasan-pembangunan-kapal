## Laporan Harian — Uraian Aktivitas & Lampiran
- Kategori aktivitas = Work Group Kurva-S data kapal (`laporan_aktivitas.kurva_s_work_group_id`, null = "Lainnya") + snapshot nama di `kategori`.
- Foto lampiran 1:1 dengan aktivitas (`laporan_lampiran.laporan_aktivitas_id`, unique). `laporan_harian_id` tetap ada untuk Laporan Mingguan. `LaporanLampiran::keterangan` adalah accessor = uraian aktivitas (eager load `aktivitas`).
- File lampiran/NC di-serve via route `laporan-lampiran.file`, `laporan-nc-foto.file` & `laporan-nc-form.file` (permission `laporan_lampiran_preview` + `User::canAccessDataKapal` scope, `isFileCompleted`) — JANGAN kembalikan base64 data-URL ke public prop Livewire (penyebab PayloadTooLarge di form mingguan). `LaporanLampiran`, `LaporanNcFoto` & `LaporanNcForm` memakai `HasEncryptedRouteKey`.
- Simpan aktivitas + foto selalu lewat `LaporanHarianService::syncAktivitas()` (transaksi, update by id, hapus foto aktivitas yang dihapus). Form memakai `row_key` stabil; foto di state dikunci per `row_key`, bukan index.
- Template harian dinormalisasi via `php build_laporan_harian_template.php` (idempoten): font Arial 10pt seragam (rFonts run dihapus), blok info = tabel tanpa garis label | : | nilai, judul section A–F biru tua, header tabel `1F3864`.
- Template Word harian memakai blok `${blok_kategori}`…`${/blok_kategori}` (judul `${aktivitas_kategori}` + tabel aktivitas) dan `${blok_lampiran}`…`${/blok_lampiran}` (grid 2x2 `${lp_kategori_N}`, `${lp_gambar_N}`, `${lp_uraian_N}`, N=1..4, plus `${lampiran_pemisah}`, `${lampiran_kosong}`). Template custom per Data Kapal wajib memakai placeholder yang sama.

## Laporan Mingguan — Word
- Template dibangun ulang via `php build_laporan_mingguan_template.php` (cover, info proyek, A–E, pengesahan). Header tabel biru tua `1F3864`, teks putih.
- Tabel tanpa gambar dibangun di `LaporanMingguanWordService` via `setComplexBlock`: `${tabel_kurva_s}`, `${tabel_uraian}`, `${tabel_nc}`, `${tabel_external}`. Foto memakai `${blok_foto}` (`fh_*`, cloneRow + setImageValue).
- `${ringkasan}` dibungkus `${blok_ringkasan}` dan di-clone per baris input (`fillRingkasan`): `setValue` mengubah `\n` menjadi `<w:br/>` dalam satu `<w:p>` — di paragraf justify (`jc="both"`) baris sebelum break ikut di-stretch selebar margin. Template custom lama tanpa blok tetap didukung (fallback `setValue` biasa).
- Lampiran E.2: paragraf `${lampiran_harian}` diganti halaman sampul "LAPORAN HARIAN" (sel tabel setinggi halaman — `vAlign`+`jc` center; tinggi 13400 twip menyisakan ruang untuk paragraf page-break agar tidak ada halaman kosong) + `w:altChunk` (tiap harian diawali page break) berisi docx harian utuh (tampilan identik template harian). Sumber: `doc_path` harian yang sudah ada; bila belum ada di-generate via `GenerateLaporanHarianJob::dispatchSync`. altChunk hanya dirender MS Word (desktop/365), tidak di LibreOffice/Google Docs/preview browser.
- NC mingguan (`LaporanNcService::rekapMingguan`): open terbawa terus, closed hanya tampil di periode ia di-close.

## Laporan Bulanan — Word
- Saat memakai ulang DOCX mingguan, cocokkan jumlah `altChunk` dengan `laporan_harian_count` (query `withCount`); mingguan lama tanpa lampiran harian dibuat ulang via Job yang sama. Kegagalan/ketidaklengkapan lampiran harus menggagalkan bulanan, bukan diabaikan. `WordChunkService::flatten()` meratakan DOCX bertingkat ke paket bulanan satu tingkat, mempertahankan urutan dan seluruh resource/styles/header per segmen tanpa memodifikasi sumber; page-break batas dipasok embed bulanan agar tidak muncul segmen kosong antarharian. Test harus memakai storage terisolasi karena Job dapat menghapus file lama.
- PhpWord 1.4.0 dipakai tanpa patch vendor/plugin Composer. `WordStyleService` menyiapkan paragraph style melalui API resmi (numStyle kosong eksplisit hanya jika null) sebelum writer dipanggil; nomor asli tidak diubah. Gunakan `prepare()` sebelum menyimpan dokumen build, dan `setComplexBlock()` helper untuk tabel runtime bulanan/mingguan. Jangan menyembunyikan deprecation vendor.
- Sesuai keputusan pengguna, TOC mengikuti pola survey: field/template + bookmark/hyperlink/PAGEREF, pembaruan oleh Word; tidak ada renderer server dan rencana renderer dibatalkan. updateFields/dirty tidak menjamin pembaruan otomatis pada semua konfigurasi Word.
- TOC hasil build berisi 22 entri hyperlink + bookmark `_MonthlyToc*` + nested `PAGEREF` dirty, dengan TOC1/TOC2 bertingkat dan tab kanan dotted. Nilai halaman awal `—` (bukan angka perkiraan); Word menghitung saat dibuka. Placeholder nama kapal juga ada di entri TOC dan diisi TemplateProcessor bersama heading.
- Warna nomor otomatis wajib diatur di `word/numbering.xml/w:lvl/w:rPr`, bukan hanya font teks judul: BAB/subbab biru `1F4E79`. Subbab left=720/hanging=720 twip (posisi nomor tepat di margin kiri, sesuai contoh pengguna); poin lingkup dan Kata Pengantar memakai definisi indent yang sama (left=720/hanging=360/tabPos=720 twip), tetapi numId terpisah agar masing-masing mulai dari 1.
- Uji Job jangan mengandalkan `doc_path=null` pada objek untuk melindungi file lama: dispatchSync menserialisasi/memuat ulang model, sedangkan rollback DB tidak mengembalikan file yang dihapus Job. Gunakan fixture terisolasi untuk pengujian lifecycle file.
- Acuan judul BAB memakai satu paragraf numbering dengan line break sebelum nama BAB (nomor di baris pertama, nama di baris kedua), rata kanan 20 pt, border bawah 24; subbab 13 pt. Field TOC meratakan line break menjadi spasi.
- PhpWord tidak menghitung pagination. Template survey kondisi menyimpan cache TOC dari master, bukan hasil hitung halaman dinamis di PHP. Verifikasi pembukaan otomatis dan pembaruan manual Word secara terpisah; server tujuan Linux/tanpa Word, jangan memasang ketergantungan Word COM pada generator.
- Template dibangun ulang via `php build_laporan_bulanan_template.php` (cover, pengesahan, daftar isi, kata pengantar, exec summary, BAB 1–4). Tabel via `setComplexBlock` (`${tabel_*}`); `${lampiran_mingguan}` diganti `w:altChunk` docx mingguan utuh (pola harian→mingguan).
- Penomoran memakai `w:numPr` asli (bukan teks literal): numbering `numJudulBab` ter-link `pStyle` `JudulBab1` (`BAB %1.`) & `JudulBab2` (`%1.%2.`) + post-process menyuntik `numPr` balik ke definisi style; poin list via `addListItem` numbering `numPoin`. Judul tanpa nomor (LEMBAR PENGESAHAN, DAFTAR ISI, KATA PENGANTAR, EXECUTIVE SUMMARY) pakai `JudulBab0`/`JudulBab0C` — tetap di TOC level 1. `INFORMASI UMUM` sengaja tanpa style bernomor (tidak masuk TOC, seperti contoh).
- TOC memakai `TOC \t "JudulBab0;1;JudulBab0C;1;JudulBab1;1;JudulBab2;2" \h \z` (tanpa `\o`/`\u`) untuk membatasi entri ke style bulanan. Pemisah mapping mengikuti regional Word: Word lokal membutuhkan titik koma; koma terbukti menghasilkan "No table of contents entries found" saat diuji via Word COM. `updateFields=true` + field `dirty=true`; verifikasi rendering dengan Microsoft Word, bukan validitas XML saja. Jangan simpan ulang template melalui Word karena placeholder dan cache TOC belum berisi data laporan.

## NC — Foto & Form NC (Non Conformance Report)
- Lampiran NC sekarang 1:N (`laporan_nc_foto.laporan_nc_id` tidak unique): `NcFileKategori` Before/After; gambar/PDF. Nama internal model/route `LaporanNcFoto` tetap dipakai. Form harian menambah Before via `syncNc`; List NC menambah Before/After via `addFiles`. State upload per slot `{row_key}_{uuid}`; file baru tidak menggantikan lampiran lama. Tambah/hapus file tidak dibatasi status NC dan tidak menutup NC; tetap authorize update + scope kapal. Preview/thumbnail di Edit & Show lewat `HasNcFotoPreview`.
- `ProcessNcFoto` menyimpan gambar sebagai WebP q85, PDF asli + `rendered_pages` WebP (urutan halaman). `PdfPageService` memakai Poppler `pdfinfo`/`pdftoppm` (argument array, bukan shell): konfigurasi `PDFINFO_BINARY`/`PDFTOPPM_BINARY`; default nama executable dari PATH. Windows lokal memakai portable di `storage/app/tools/poppler` (gitignored); Linux perlu paket `poppler-utils`. Batas resource: 200 halaman, rendering 45 detik, timeout Job 60 detik. File gagal tidak boleh diabaikan saat generate Word.
- `NcAttachmentWordService` memasukkan halaman PDF sebagai gambar halaman penuh ke DOCX (bukan OCR/altChunk PDF); foto melalui format lampiran. Source/cached image WebP memakai helper `WordImageService` untuk encoding dokumen. Signature lampiran disimpan pada ZIP archive comment; bulanan memeriksa signature DOCX mingguan dan meregenerasi jika file NC ditambah/dihapus/berubah, tanpa mengubah hitungan altChunk harian.
- Verifikasi tambahan: `php artisan test --filter="NcAttachmentProcessingTest|LaporanNcTest|LaporanNcFormTest|LampiranFileRouteTest|LaporanMingguanWordServiceTest|LaporanBulananTest"`. Test renderer nyata akan skip jika executable Poppler tidak terkonfigurasi.
- Form NC (`laporan_nc_form` + pivot `laporan_nc_form_item`, `LaporanNcFormService`): **Form Temuan** per laporan harian (draft disegarkan tiap generate ulang, hanya NC yang belum masuk form temuan bertanda tangan) & **Form Penutupan** lintas hari (NC Open yang belum ada di draft penutupan lain). Nomor `{kode kapal}-NCR-xxx` per kapal. Status diturunkan dari `file_status` (`NcFormStatus`), `signed_at` null = draft.
- Generate Word NCR - CLOSE hanya memakai lampiran After (foto dan semua halaman PDF), tanpa fallback Before jika After kosong. Filter tunggal di `LaporanNcWordService` diterapkan ke salinan relasi untuk kedua jalur lampiran; relasi sumber dan export mingguan/bulanan tidak diubah.
- NC **hanya ditutup** lewat upload scan TTD Form Penutupan (`uploadSigned`, satu transaksi). Reopen di List NC (`LaporanNcService::reopen`). Draft bisa dihapus, form bertanda tangan tidak.
- Gate::before super admin mem-bypass cek state di `LaporanNcFormPolicy::delete` — Blade & component tetap cek `isDraft()` eksplisit.
- Dokumen Word digenerate on-the-fly (`LaporanNcWordService`, file temp + `deleteFileAfterSend`). Template default dibangun `php build_laporan_nc_template.php` dari master `storage/app/templates/laporan-nc/master-nc.docx` (salinan NC.docx). Placeholder: `${nama_proyek}`, `${judul_form}`, `${nomor_ncr}`, baris `${nc_no}` (diisi nomor NC, mis. NC-001 — kolom "No" di semua tabel NC Word: form, mingguan `tabel_nc`, bulanan `nc_no`) `${nc_masalah}` `${nc_tanggal}` `${nc_pic}` `${nc_status}` `${nc_selesai}` `${nc_tindakan}`, blok `${blok_lampiran}`…`${/blok_lampiran}` dengan baris `${foto_no}` `${foto_gambar}` `${foto_keterangan}`. ## PhpWord TemplateProcessor gotchas
- `findRowStart()` mencari `<w:tr ` (dengan spasi) lebih dulu: baris tabel yang ditulis manual sebagai `<w:tr>` membuat `cloneRow`/`deleteRow` memotong dari baris tabel lain. Selalu beri atribut, mis. `<w:tr w:rsidR="00C0FFEE">`.
- Aktifkan `Settings::setOutputEscapingEnabled(true)` sebelum `setValue`; teks seperti "Engineering & Design" merusak XML dokumen bila tidak di-escape.
- JANGAN pakai auto-numbering Word (`w:numPr`) untuk judul yang teksnya sudah memuat huruf/nomor literal — hasilnya ganda ("A. A. ..."). Lebih fatal: docx harian disisipkan ke laporan mingguan via `w:altChunk`; list numbering LANJUT antar-chunk (judul laporan harian ke-2 mulai dari "F"). Tulis nomor literal di teks, lepas `numPr`/`ListParagraph`/`w:ind` dari paragraf judul.
- Tabel ber-lebar `dxa` tanpa `tblLayout fixed` bisa menyusut mengikuti isi sel (autofit) — tampak lebih pendek dari tabel lain yang `pct`. Selaraskan semua tabel konten ke `tblW 5000/pct` + `tcW` persen (gridCol tetap dxa).
- `LaporanHarianWordService::generate()`/`LaporanMingguanWordService::generate()` hanya menulis file — `doc_path` di-update oleh `GenerateLaporan*Job`. Jangan panggil service langsung untuk regenerate; pakai `GenerateLaporanHarianJob::dispatchSync($laporan)` agar file lama terhapus & `doc_path` menunjuk file baru (lampiran mingguan membaca `doc_path`).
